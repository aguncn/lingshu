## Why

会话界面目前只能看到模型最终文本：它到底调用了哪些命令/MCP、读了哪些文件、思考过程如何——既不展示、也不落库，跑完即失，无法回看。运维场景要信任并复核智能体的动作，就必须能追溯「这一次回答它做了什么」。现状同时缺少结构化的「调用摘要」：每条助手回复没有独立成行的过程头，回复与回复之间视觉易粘连；对话字号固定且偏大。

## What Changes

- **字号**：会话正文字号抽成 CSS 变量并整体调小（默认 13px 档），随明/暗主题沿用。
- **每条助手回复结构化为三段**：顶部独立一行的「调用摘要」+ 正文 + 可内嵌展开的「过程明细」；不同回复以摘要行分隔，不再视觉粘连。
  - 摘要行轻量呈现本轮真实发生的调用（命令/文件工具、MCP、二次确认），形如 `调用了 Bash ×2 · MCP[jenkins]`。
  - 展开「过程明细」就地显示该回合有序步骤：思考片段、工具入参与结果成败摘要、确认决策。入参/结果为摘要级（不落密钥、超长截断，延续现有限额约定）。
- **流式进行中**：正文占位以动态 "…" 呈现思考/回复过程；摘要位随工具事件实时累积，提供「查看过程」小入口，运行中即可展开看实时过程。
- **服务端把过程随消息落库**：每次助手回合结束时，将本次运行的有序步骤 trace 随该助手消息持久化；`GET /api/tasks/<id>/messages` 对助手消息额外返回结构化 `trace`（**可选新增字段，向后兼容**，旧字段不变）。刷新页面或重开任务后仍可展开回看 → 真正可追溯。模型失败/未产文本的运行只保留用户消息、不产生伪助手 trace。
- **技能/资料库本期不提升为可调用工具**：只在摘要旁以「已装配能力」展示任务当前挂载（技能/资料库/MCP 名称），并明确区分「已装配」与「已调用」，不伪称被调用。其可调用化由后续独立提案承担，本提案不接知识库检索。
- 二次确认卡片、停止、错误态、按任务隔离等既有行为保持不变；不改 SSE 事件契约。

## Capabilities

### New Capabilities

（无新增能力域：过程追溯的记录面归属运行时的消息持久化契约，展示面归属工作台会话区。）

### Modified Capabilities

- `agentscope-runtime`：将「对话历史持久化与读取」扩展为——每次助手回合的最终文本之外，还持久化该回合的有序过程 trace（思考片段 / tool_call 名+参数 / tool_result 成败+摘要 / 确认决策），并随 `GET /messages` 对助手消息一并返回（可选字段、向后兼容）；因模型错误未产文本的运行不产生伪 trace。
- `workbench-ui`：将「会话区与任务文件树」「会话输入与智能体实时会话」的渲染扩展为——助手气泡由「独立成行的调用摘要 + 正文」构成、摘要可展开为就地「过程明细」；流式期间以动态 "…" 呈现思考/回复并支持实时展开；会话正文字号可调小。会话历史载入/回放同时渲染服务端返回的 trace。

## Impact

- **Backend**：`models.py` + `migrations/NNNN_*.sql`（助手回合 trace 存储：随消息或按 run 归属的新增结构）；`services/agent_session.py` 在回合内累积步骤、done 时随助手消息落 trace；`services/message.py` 落 trace 并在 `list_messages` 随消息返回；`GET /messages` 输出向后兼容增量；相应 `pytest`。
- **Frontend**：`api/chat.js`（消息类型带 trace）、`stores/task.js`（流式期间累积 trace 到 live 气泡、历史映射 trace）、`ChatPane.vue` 及新增的过程摘要/展开子组件、样式 token（字号变量）。
- **不引入**：新依赖/中间件、SSE 事件类型变更、技能/资料库可调用（另立提案）、向量化/知识库检索接入、时间线页签接入（另行排期）。
- **验收**：后端单测（含工具回合的 trace 落库与返回、无工具纯文本回合 trace 为空、失败运行无伪 trace）+ 前端手工验收清单（字号、独立摘要行、展开/收起过程、流式 …、刷新后可回看）。
