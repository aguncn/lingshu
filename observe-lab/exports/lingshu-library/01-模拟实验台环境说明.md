# observe-lab 模拟实验台 · 环境说明（资料库参考件 01）

本文件是「灵枢 × OpenObserve 模拟故障智能诊断」实验台的环境底稿。模型在做诊断前应先读本件，
确认自己在看什么系统、数据落在哪，避免把模拟电商环境当成生产或编造字段。

## 这是什么
- 一套**模拟电商在线交易平台**的观测数据，真实写入一台自托管 OpenObserve（本文按 `http://localhost:5080`，org=`default`）。
- 数据经 O2 真实 API/OTLP 写入，可在 O2 里 SQL/PromQL 查询、能出仪表盘、能触发告警。只做实验台，不代表真实生产。

## 命名空间 `ec_`（最重要的约定）
实验台的一切都用 `ec_`/`ec-` 前缀，与 O2 实例里可能存在的旧数据（fin_/tel_/rum_data 等）彻底隔离：
- 日志流：`ec_access_logs / ec_application_logs / ec_system_logs / ec_audit_logs / ec_rum_pageview / ec_rum_error`
- 指标：metric 一律 `ec_` 开头（`ec_http_request_rate` …），且 **metric 名即 O2 流名**（PromQL 里直接写 family 名）。
- 服务名：`ec-gateway / ec-order / ec-payment / ec-product / ec-search / ec-cart / ec-inventory / ec-user / ec-web`
- 追踪：OTLP 落 O2 的 `default` traces 流，`service_name` 均为 `ec-*`。
- 仪表盘标题、告警规则名均带 `E-commerce`/`ec-`。

**查询任何数据都先锁 `ec_` 命名空间，不要碰 fin/tel/rum_data 旧流。**

## 内置 6 条故障（诊断对象）
每条故障都会：在错误日志里留下**可全文搜的关键字**、在 PromQL 上出现**特异曲线**、必要时在审计流里留下**变更记录**、前端故障会表现为 **RUM JS 报错/资源 404**。

| 故障 | 一句话根因 | 一眼关键字 |
|---|---|---|
| F1 订单库连接池耗尽/慢 SQL | 建索引 DDL + 全表扫描报表把连接池占满 | `ER_LOCK_WAIT_TIMEOUT` `pool exhausted` `query too slow` |
| F2 Redis 热点键击穿/雪崩 | 主推位未预热 + maxmemory 策略改 LRU 致整片回源 | `cache stampede` `MISS burst` `evicting keys` |
| F3 支付回调 Kafka 积压 | v2.3.1 回调线程加远程校验，消费变慢 | `lag=` `state still pending` `max.poll.interval` |
| F4 网关误限流+单实例剔除 | 路由权重 100/0 + 误启限流 zone | HTTP `429/502/503` |
| F5 节点磁盘 90%+证书过期 | 备份清理 cron 停用致磁盘满、ACME 续期失败 | `No space left` `certificate has expired` |
| F6 前端发版 JS 报错 | 灰度 2.4.0 部分 index.html 仍引用旧 chunk → 404 | `app.7f3a.chunk.js` `Cannot read properties` |

完整 runbook：导入知识库后检索 `fault-F1.md` … `fault-F6.md`；或看本仓库 `qa/fault-F*.md`。

## 与诊断相关的两个“版本事实”
1. **指标有 1~3 分钟异步索引**：刚灌完 PromQL/面板可能空白或不全，等一两分钟即稳定；诊断时若某窗口查询为空，先放大时间窗再刷一次。
2. **追踪不能用 SQL 查**：traces 只走 OTLP 的 `default` 流，用 O2 Traces 页/MCP 的 GetLatestTraces 按 `service_name = ec-*` 过滤；日志里的 `trace_id` 可与追踪对齐。
3. **告警规则 REST 建不了**（本 O2 v0.92.2）：诊断时把“看告警”落实为“对现场反查”（查错误日志计数/指标特征），而不是依赖 O2 的告警 CRUD 工具。

## 术语速记
- 日志/指标/链路/RUM 的字段全名见 `02-O2-SQL日志查询速查.md` 与 `03-O2-PromQL指标查询速查.md`（本资料库）。
- `_timestamp` 是**微秒**整数；面板/查询里选好时间范围即可。
- `status`（访问日志）是**整数**（写 `status in (429,502,503)`，别加引号）。
