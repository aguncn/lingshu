# 01 · 环境与凭据

## 你需要的东西
- Python 3.12+ 与 [uv](https://docs.astral.sh/uv/)（本项目用 uv 管理虚拟环境，不污染全局）。
- 一台可访问的自托管 OpenObserve（本文以 `http://localhost:5080` 为例）。
- OpenObserve 里一个有登录权限的账号 + 组织名（默认 `default`）。

## 1. 首次准备

```bash
cd observe-lab
uv sync                 # 按 pyproject.toml 装依赖(requests/protobuf/opentelemetry-proto)
```

## 2. 填 .env

```bash
copy .env.example .env   # Windows
# Linux/macOS:  cp .env.example .env
```

编辑 `.env`，只填你自己的四项即可（其余有默认值）：

```dotenv
OO_BASE_URL=http://localhost:5080
OO_ORG=default
OO_EMAIL=admin@abc.com        # ← 改成你的 O2 登录邮箱
OO_PASSWORD=Root@1234         # ← 改成你的 O2 登录密码
```

`.env` 已被 `.gitignore` 忽略，含明文账号，别提交。

> 若你希望**不改 .env**，也可以用环境变量覆盖，如 `OO_PASSWORD=xxx uv run python sim/main.py …`。

## 3. 自检：让脚本告诉你这台 O2 支持什么

```bash
uv run python selftest.py            # 常规自检
uv run python selftest.py --verbose  # 打印每条 API 调用细节
```

它逐项探测并打印 ✅/⚠️/❌：

1. 连接 + 登录鉴权（账密错会立刻红）
2. 服务端版本
3. 日志 `_json` 写入 + `_search` 可查回（单位=微秒）
4. OTLP 链路写入（落 `default` traces 流）
5. OTLP 指标写入 + PromQL 可查
6. 原生 MCP 端点可达性（灵枢 http 直挂 O2 用）
7. 告警规则列接口形态
8. 仪表盘接口
9. 历史回填深度（默认约 5h 上限的探测）

结论写进 `.cache/capabilities.json`；**全绿即可生成数据**。出现 WARN 多为“这版本能力差异”，会同时给兜底做法；出现 FAIL 先按指引修好再继续。

> 提示：自检的日志/指标探针用唯一随机流名 `ec__probe_*`，测完即删；O2 删流是异步的，偶尔列表里残留 1 条空流属正常，不影响使用。

## 4. 常见问题

**连不上 / 401**
- 核对 `.env` 的 `OO_BASE_URL`（要带 `http://`）与邮箱/密码/组织名。
- 自检第 1 步会直接报鉴权失败并终止，不用往下猜。

**`Too old data, only last 5 hours… / ZO_INGEST_ALLOWED_UPTO`**
- 你在回填超过约 5 小时的历史数据，服务端默认不允许。解决见 `docs/02` 的「多天回填」小节（设环境变量并重启 O2）。

**Windows 终端乱码/方块字**
- 入口脚本已强制 UTF-8 输出；请在 Windows Terminal / VS Code 终端里运行。个别老控制台仍异常时可临时 `set PYTHONIOENCODING=utf-8`。
