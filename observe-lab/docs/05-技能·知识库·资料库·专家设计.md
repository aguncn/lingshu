# 05 · 技能 / 知识库 / 资料库 / 专家 设计

这四类是灵枢让模型“**带着能力去诊断**”的载体。observe-lab 导出的整套放在 `exports/`，
本文说明“为什么这么拆、每份文件干什么、在灵枢里运行时是什么形态”。导入动作见 `exports/import-checklist.md`（UI）或 `exports/import_via_api.py`（一键）。

## 角色分工一句话
| 载体 | 灵枢形态 | observe-lab 放什么 | 目的 |
|---|---|---|---|
| **技能 Skill** | 只读 `skill_<slug>` 工具（挂载且 enabled、有正文才可用） | 5 条 `o2-sre-*`：值班拉现场 / 查日志SQL / 查PromQL / 查链路 / 写报告 | 教会模型“**怎么操作 O2**”：工具用法、SQL/PromQL 铁律、报告格式 |
| **知识库 KB(RAG)** | 挂载的 **ready** KB 才进 `knowledge_search`，按 chunk 关键词检索 | `fault-F1..F6.md` runbook + 命名索引，共 7 篇 | 让模型能**检索“相似历史故障”**对样，给根因增信 |
| **资料库 Library** | 文件以引用方式挂到任务，模型可**读原文/引用** | 3 篇速查：环境说明 / SQL 字段字典 / PromQL+label 字典 | 给模型一份**“别编字段名”的权威对照表** |
| **专家 Expert** | `role=ops-sme`；`expert/apply` 时把 `system_prompt` 快照到任务；预设=一次勾好上面三类 | 「SRE 值班专家·observe-lab」 | 一键把“人设 + 工具 + 知识 + 参考”打包到任务 |

> 为什么资料库和知识库都放“速查”类内容会重复？在灵枢里两者读取方式不同：**KB 是模糊检索命中片段**（适合“异常长什么样/怎么处置”），**资料库是整篇可引用**（适合“字段叫法/查询口径”这种要精确、别靠回忆的内容）。给模型同一份权威参考的两种拿法，二选一或都要都行。

## 运行时几个口径（写文档/排查用）
1. **生效时机**：灵枢每轮聊天重建 agent → 改完挂载 **发下一条消息**即生效，不用重启。
2. **技能**：需 `enabled` 且有正文（`skill_md`）才算可用工具；本文导出都满足。
3. **知识库**：只有状态 **ready** 的 KB 会进检索；上传走 `.md` 文本、按 chunk_size(400) 切块、关键词检索（本项目默认无向量）。
4. **资料库**：`expert/apply` 会**以引用方式幂等挂到任务**（不拷字节）；同名文件重传会覆盖 KB 里该文件的 chunks，但资料库同名文件不会自动更新（先删旧的）。
5. **专家 apply**：全量覆盖任务的 skills/mcps/kbs 挂载 + `experts=[专家id]`，并把 `system_prompt` 快照成 persona；预设里 disabled/未 ready 的项进 `skipped` 不会中断；`default_provider_id` 有才绑模型（本演示可不绑，任务侧手动选模型即可）。
6. **MCP**：capability 挂载只按 `enabled` 过滤，但运行时 `is_mountable = enabled 且 trust` —— 所以 `openobserve-ec` 必须 **trust 打开**，否则工具不出现。

## 本实验台“为什么这样设计”
- **告警 CRUD 在这版 O2 建不了** → 技能 `o2-sre-triage` 教模型“没告警接口就用日志/指标反查现场”，不把诊断吊死在告警接口上。
- **最容易翻车的是编字段名** → 资料库 02/03 把 6 个流 + 全部 metric + label 写死成字典，专家 persona 里也明确“拿不准先 StreamSchema/查速查”。
- **根因判断需要“对样”** → 6 条 runbook 进 KB，模型检索到 `fault-F3` 的特征曲线就能对照当前 Kafka lag 是否一致。
- **报告要能复核** → `o2-sre-report` 强制“结论带证据查询”，避免模型输出像诊断、其实没查过。

## 想自己扩展
- 加技能：`exports/lingshu-skills/xxx.md` → 技能中心建一条（正文即 SKILL.md）。
- 加故障 runbook：跑 `tools/make_qa_docs.py` 会用 `sim/incidents.py` 的 RUNBOOKS 重新生成全部 qa + lingshu-kb 文档（单一事实来源在 incidents.py）。
- 改速查：直接编辑 `exports/lingshu-library/*.md` 后重传资料库（KB 同名会覆盖）。
