# 灵枢 (Lingshu) 产品需求列表 · PRD v0.3（修订版）

> 文档状态：已整合全部需求讨论，UI 布局按 WorkBuddy 范式完成修订。
> 适用范围：IT 运维领域专用智能体平台（非通用平台）。
> 生成日期：2026-09-05

---

## 0. 产品定位

| 项 | 内容 |
|---|---|
| 名称 | 灵枢 (Lingshu) |
| 定位 | 面向 **IT 运维领域**的智能体平台（非通用型）。以「任务」为最小运行单元，将大模型 + 技能 + MCP + 知识库 + 专家装配为可复用的运维智能体 |
| 目标用户 | 运维工程师、SRE、DBA、中间件管理员、运维负责人 / 管理者 |
| 设计基调 | 生产级工业风格，信息密度高、专业可信，参考 Datadog / Grafana / Linear 的视觉语言，拒绝卡通与花哨渐变 |
| 核心差异 | 12 大运维场景域，每域有独立提示词模板与差异化的上下文注入 / 能力装配 |

---

## 1. UI / 交互设计规范（修订版 · 参照 WorkBuddy）

> 核心范式：**左栏管「资产与入口」，右栏管「本次对话的执行上下文」**。

| 编号 | 需求 | 说明 |
|---|---|---|
| **UI-01** | 整体布局（左导航 + 右会话） | **左栏（全高）**：顶部①新建任务；②导航项「专家·技能·MCP 连接器 / 自动化任务 / 资料库」；中部「任务列表」（按空间分组、可搜索）；底部「个人信息 + 设置中心」。<br>**右栏**：顶部「常用工作任务分类 + 提示词模板」；中部「任务会话（对话 + 文件树 / 预览）」；底部「可折叠细节栏 + 输入框」 |
| UI-02 | 视觉风格 | 中性灰底 + 品牌强调色（蓝 / 青），专业线性图标，表格 / 列表为主，支持暗色模式 |
| UI-03 | 核心组件 | 命令面板 (Cmd+K)、抽屉（用于打开注册中心 / 设置）、状态徽标、时间线（故障 / 变更记录） |
| UI-04 | 一致性 | 统一卡片 / 空状态 / 加载态 / 错误态；不卡通、不渐变 |
| UI-05 | 信息密度 | 默认高密度，关键指标图表化（趋势线 / 状态灯） |
| **UI-06** | 可折叠会话细节栏 | 输入框上方提供「模型 / 技能 / 资料 / MCP / 工作空间 / 权限模板」入口，默认收起为「…」或「+」，点击展开逐项指定；**本次会话的挂载覆盖任务模板默认值** |
| **UI-07** | 设置中心 | 底部「设置」入口内含：模型接入（供应商 / API Key / endpoint / 默认模型）、个人信息、全局偏好、主题 |

### 布局逻辑（一句话）
左栏管「资产与入口」（任务、注册中心、自动化、资料库、设置），右栏管「当前任务的执行上下文」（分类 / 模板 → 会话 → 可折叠地指定模型 / 技能 / 资料 / MCP / 工作空间 / 权限）。通用能力收进左导航，当前任务参数收进输入区上方，既干净又不玩具感。

## 2. 任务与空间管理（TR）

| 编号 | 需求 | 判据 / 说明 |
|---|---|---|
| TR-01 | 新建任务 | 任务必须归属某「空间（Space）」；创建时可命名、选任务类型、绑模型 |
| TR-02 | 空间管理 | 空间的创建 / 列表 / 切换 / 删除；空间是隔离与协作边界 |
| TR-03 | 权限设置 | 空间 / 任务级权限：私有 / 团队 / 公开；角色至少含 Owner / Editor / Viewer |
| TR-04 | 重命名 | 任务名 / 空间名可改，重命名后文件目录与引用同步更新 |
| TR-05 | 打开工作空间 | 一键打开任务工作区，浏览 / 检索 / 预览 / 下载该任务生成的所有文件（代码、文档、图片、表格、音视频等） |
| TR-06 | 文件持久化隔离 | 文件按「空间 → 任务」两级目录落盘（本地或对象存储），任务删除 / 归档时文件可一并处理 |

> 说明：新建任务入口在左栏顶部（UI-01）；工作空间选择与权限模板下沉到会话细节栏（UI-06），与能力装配同处。

---

## 3. 模型与提示词配置（MD）

| 编号 | 需求 | 说明 |
|---|---|---|
| MD-01 | 每任务 / 每会话选模型 | 任务级或本次会话绑定大模型，支持多供应商（OpenAI / 国产模型 / 本地模型）；可配 temperature、max_tokens、超时等参数 |
| MD-02 | 常用任务类型 | 预置运维任务模板（写文档 / 写代码 / 数据分析 / 排障等），新建任务可一键套用 |
| MD-03 | 提示词库 | 领域提示词 / 系统提示词管理：可保存、分类、复用、版本化；任务可直接引用 |
| MD-04 | 模型供应商配置 | 置于设置中心（UI-07）：增删模型供应商、配置密钥 / endpoint、设默认模型；对接 MD-01 的可选模型清单 |

> 说明：MD 拆为两层 —— 运行态选模型（MD-01，落在会话细节栏 UI-06）；供应商接入配置（MD-04，落在设置中心 UI-07）。

---

## 4. 任务能力装配（CAP）

| 编号 | 需求 | 说明 |
|---|---|---|
| CAP-01 | 挂载专属技能（Skills） | 每个任务 / 会话可勾选若干技能（如 SQL 分析、报告生成、Ansible 自动化等），也可指向用户自定义技能 |
| CAP-02 | 挂载 MCP 连接器 | 每个任务 / 会话可启用 MCP（如 DB 只读、监控、日志、CMDB、告警等），按任务粒度启用，避免全局污染 |
| CAP-03 | 挂载知识库文件 | 每个任务 / 会话可绑定知识库 / 资料文件，作为检索增强（RAG）上下文 |
| CAP-04 | 绑定专家 | 每个任务 / 会话可指定角色化专家（单一专家或多专家协作），决定任务默认的「人设」与流程 |

> 说明：能力装配改为按需挂载，技能 / 资料 / MCP 不再常驻右栏，改为会话细节栏中按次会话挂载，可折叠（UI-06）。

## 5. 统一管理后台 / 注册中心（AD）

> 专家、技能、MCP 连接器的统一编辑管理入口；由左栏「专家·技能·MCP 连接器」导航打开（抽屉 / 独立页）。

| 编号 | 需求 | 说明 |
|---|---|---|
| AD-01 | 技能中心 | 技能的创建 / 编辑 / 导入 / 发布 / 版本管理（含 SKILL.md 编辑与预览） |
| AD-02 | MCP 连接器中心 | 增删改查与配置（command / args / env / headers / url）、连通性测试、信任开关（启用前需信任） |
| AD-03 | 知识库中心 | 文件上传 / 解析 / 向量化 / 检索配置；可授权给指定空间或任务 |
| AD-04 | 专家中心 | 专家 / 专家包的创建、编辑、组合（多角色协作编排）、启用 / 停用 |

## 8. 智能体场景域（核心差异点 · 12 大运维域）

> 每个场景域有**独立提示词模板**，对应不同的推理目标、上下文注入与装配能力。

| 域 | 智能体职责 | 提示词设计要点 | 建议装配 |
|---|---|---|---|
| 监控巡检 | 定时巡检指标，识别异常趋势 / 偏离，输出巡检报告 | 基于时间序列 + 阈值 + 基线；输出分级结论与处置建议；抑制误报；注入对象拓扑与指标字典 | 监控 MCP、巡检规范库、报告技能 |
| 日志隐患 | 识别 ERROR / 异常栈 / 安全风险 / 敏感泄露 | 多行日志上下文关联；区分噪声与真隐患；给定位线索（时间 / 主机 / 链路） | 日志 MCP (ES/Loki)、日志解析技能 |
| 数据库性能排查 | 慢 SQL / 执行计划 / 锁等待 / 索引与参数建议 | 基于真实执行计划与统计信息推理；给可验证 DDL；禁止盲目改生产 | DB 只读 MCP、执行计划手册、DBA 专家 |
| 中间件安装配置 | Redis / Kafka / Nginx 等部署、调优、高可用 | 输出可执行步骤 + 回滚；参数带默认值与取值范围；环境前置检查 | Ansible / SSH 技能、官方最佳实践库 |
| 告警 | 降噪 / 去重 / 分级 / 根因关联 / 抑制 | 区分告警与故障；基于拓扑收敛；给处置优先级 | 告警 MCP、CMDB MCP、告警分级策略库 |
| 故障诊断 | 定位 / 影响面 / 时间线 / 根因假设验证 | 假设 — 验证闭环；多维证据（指标 / 日志 / 链路）；输出影响面与 MTTR | 监控 + 日志 + 链路 MCP、CMDB、SRE 专家 |
| 变更风险 | 方案评审 / 风险预判 / 回滚评估 / 灰度 | 基于类型与依赖拓扑评估爆炸半径；列风险项与缓解 | CMDB MCP、工单 MCP、变更规范库 |
| 容量预测 | 历史指标外推，预测耗尽时间，给扩容建议 | 说明方法与置信区间；区分周期 / 趋势；给阈值与时间窗 | 监控 MCP、时序分析技能、容量模型库 |
| CMDB 数据治理 | 质量校验 / 一致性 / 缺失补全 / 关系纠偏 | 基于事实与拓扑规则校验；输出可治理工单；不臆造属性 | CMDB MCP、数据标准库、校验技能 |
| 知识库问答 | 基于 SOP / 预案做检索增强问答 | 必须引用来源；无法确认显式说明；优先最新版本文档 | 知识库（向量检索）、文档解析技能 |
| 应急预案生成 | 针对场景生成预案 / SOP（研判 / 处置 / 责任 / 逃生） | 步骤可执行；含回滚与升级路径；与现有预案风格一致 | 历史预案库、模板技能、运维负责人专家 |
| 运维脚本编写 | 生成 Shell / Python / Ansible / SQL 脚本 | 幂等、参数化、危险操作二次确认、不硬编码密钥 | 代码沙箱、Ansible 技能、内部规范库 |

## 9. 提示词工程统一要求

- 每域有独立提示词模板（系统提示 + 任务模板），存于提示词库可版本化（MD-03）。
- 提示词需注入领域上下文：对象拓扑、指标字典、SOP、历史案例。
- 统一约束（所有域共用）：禁止臆造数据；危险操作二次确认；回答引用来源；输出结构化（报告 / 表格 / 工单）。

---

## 10. 非功能需求（NF）

- **安全**：MCP 最小权限、DB 只读、密钥不落地、全量操作审计。
- **性能**：长任务异步、流式输出、大文件预览不卡顿。
- **多租户**：空间即租户边界，资源与数据隔离。
- **可观测**：模型调用量、成员操作留痕，便于治理与计费（审计日志）。

---

## 11. 优先级与首期范围

- **P0（首期必做）**：TR 全套、MD、CAP、AD、LB、UI 左导航 + 右会话三栏工作台（UI-01~07）、12 域提示词模板、基础 MCP 接入（监控 / 日志 / DB / CMDB）。
- **P1**：AU 自动化、变更 / 告警 / 故障深度编排、专家多角色协作。
- **P2**：容量预测模型、运维知识图谱、智能体自评与持续改进。
