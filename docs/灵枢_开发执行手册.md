# 灵枢 (Lingshu) 开发执行手册（环境 + CLAUDE.md + 命令流）

> 配套：《技术方案与架构设计》＋《开发计划与OpenSpec提案任务书》
> 目标：让你**对着本文档一步一步把系统建起来并跑起来**。单人 / Windows / uv / Vue3 / AgentScope。

---

## 1. 环境准备（Windows，一次性）

> 顺序：装 uv → 装 Node → 装 OpenSpec CLI → 建项目目录 → uv 建 Python 环境。

### 1.1 安装 uv（Python 包/环境管理器）
```powershell
# 用 PowerShell（管理员可装全局，普通用户装到 ~）
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
# 安装后重新打开终端，确认：
uv --version
# 如提示找不到，手动把 uv 加入 PATH（安装器会提示路径，通常是 %LOCALAPPDATA%\uv\uv.exe）
```

### 1.2 安装 Node.js（前端）
```powershell
# 方式 A：winget（推荐）
winget install -e --id OpenJS.NodeJS.LTS
# 方式 B：到 https://nodejs.org 下载 LTS 安装包
node --version   # 建议 >= 20
npm --version
```

### 1.3 安装 OpenSpec CLI
```powershell
npm install -g @fission-ai/openspec@latest
openspec --version          # 确认安装成功
```
> OpenSpec 在 Claude Code 中以 `/opsx:*` 斜杠命令调用。若你的版本显示为 `/openspec-*`，以 `openspec --help` 为准。

### 1.4 建立项目骨架目录
```powershell
# 在你想要的父目录（例如 D:\projects）下建 lingshu
mkdir D:\projects\lingshu && cd D:\projects\lingshu
```
> 后续所有命令默认在该目录下执行。把本套三文档也放进此目录（或 `docs/` 子目录），方便 Claude Code 用 `@路径` 引用。

## 2. 初始化 OpenSpec 并开启 verify

```powershell
cd D:\projects\lingshu
openspec init                 # 生成 openspec/ 目录（project.md + specs/ + changes/）
```
开启 **extended profile**（拿到 `/opsx:verify`、`/opsx:ff` 等）：
```powershell
openspec config profile      # 交互选择 extended；或编辑 openspec 配置开启 verify
openspec update              # 拉取/刷新技能
```
> 若你的版本没有 `config profile` 交互，直接手动确认 `/opsx:verify` 是否可用；不可用也**不影响开发**——用本文档的「验收命令 + 手工验收清单」做等价校验即可（OpenSpec 的 verify 本质也是对 specs 的场景核验）。

初始化后把 `openspec/project.md` 写成项目简述（见文末独立文件 `openspec_project.md`，直接复制）。

## 3. CLAUDE.md（粘贴即用）

> 把下面全文保存为项目根目录 `CLAUDE.md`。Claude Code 每次会话会自动读取它作为「项目规范」。

````markdown
# CLAUDE.md — 灵枢 (Lingshu) IT 运维智能体平台

你在此项目中担任**实现者**：按 OpenSpec 提案逐任务编码，保持简单、可运行、可验收。

## 1. 技术栈（不要引入额外复杂度）
- 后端：Python 3.12 + Flask + Flask-CORS + SQLAlchemy + SQLite（单文件库，路径 backend/data/app.db）。
- 包管理：uv（用 `uv sync` / `uv run`；不要手写 pip install 全局）。
- 前端：Vue 3 + Vite + Element Plus + Pinia + Axios（开发态 5173，代理 /api → 5000）。
- 智能体：AgentScope >= 2.06（Agent/ReAct、Toolkit、OpenAIChatModel、MCP 客户端、reply_stream 事件流）。
- 规范驱动：OpenSpec（`/opsx:propose` → `/opsx:apply` → `/opsx:verify` → `/opsx:archive`）。
- **禁止为单人项目引入**：Redis / 消息队列 / K8s / 微服务 / 额外中间件。单进程前后端即可。

## 2. 目录约定（见技术方案文档 §9）
- backend/：app.py、config.py、extensions.py、models.py、migrate.py、services/、api/、migrations/、seed/、prompts/、data/。
- frontend/src：router/、store/、api/、views/、components/。
- openspec/：project.md、specs/、changes/。

## 3. 编码规范
- 注释用中文，说明「为什么」；变量/函数名用英文。
- 后端：API 层只做校验+调用 service，业务逻辑放 services/；模型集中 models.py。
- 数据库变更：写 `migrations/NNNN_*.sql` 编号脚本，由 migrate.py 按 schema_version 顺序执行；不动 Alembic。
- 前端：视图放 views/，复用组件放 components/，接口封装放 api/，状态放 store/。
- 密钥：永不明文入库；用 cryptography.Fernet 加密（密钥取 LINGSHU_MASTER_KEY 或 .env），展示脱敏。
- 文件落盘：按 `data/spaces/<space>/<task>/` 两级；资料库归 `data/library/`。

## 4. AgentScope 集成要点（详见技术方案 §7）
- 模型：ModelProvider+ModelConfig → `OpenAIChatModel(model, api_key, base_url)`（OpenAI 兼容）。
- 运行时：AgentRuntime.build() 组装 Agent+Toolkit（内置工具 + 挂载的 MCP 工具 + 技能/RAG 注入）。
- 流式：Flask 同步框架跑 AgentScope 异步事件流，用「线程+queue」桥接转 SSE（见技术方案 §7.6 骨架）。
- 安全：内置写类工具（Bash/Write/Edit）默认 Permission confirm（危险操作二次确认）；调用写 AuditLog。

## 5. OpenSpec 工作流纪律
- 每个提案只做一件事（一个能力域），范围不超过 PRD 一个编号组。
- tasks.md 每条 = 一个接口/一张表/一个视图/一个迁移，单条可独立验收（8–12 条/提案）。
- 实现用 **新开干净会话** 跑 `/opsx:apply`，避免超长上下文改无关文件。
- 每完成一个提案必须 `verify` 再 `archive`；不攒一堆。
- 设计权威参考：@灵枢_技术方案与架构设计.md；任务划分：@灵枢_开发计划与OpenSpec提案任务书.md。

## 6. 运行与验证
- 后端：`uv run flask --app backend.app run --port 5000`
- 前端：`cd frontend && npm run dev`
- 测试：`uv run pytest backend/tests/ -q`
- 每次交付按提案的「验收命令 + 手工验收清单」逐项确认。

## 7. 范围外（本期不做，记 P1/P2）
自动化引擎、深度 MCP 真实连接器、多专家编排、容量预测、知识图谱、向量化 RAG（默认关键词检索）。
````

## 4. 每阶段「无脑」命令流

> 通用循环（以 P1 为例，其余提案把名字换掉、内容见《提案任务书》）：

### 4.1 通用开发循环（对每个提案重复）
```powershell
# ① 想清楚（可选，复杂提案才做）
#    在 Claude Code 输入：/opsx:explore <本提案要解决的问题>

# ② 出计划（Claude Code 生成 openspec/changes/<name>/{proposal.md,specs/,design.md,tasks.md}）
#    在 Claude Code 输入：《提案任务书》里该提案的「① /opsx:propose 提示词」全文

# ③ 你 Review：读 changes/<name>/proposal.md 与 tasks.md，按需改范围/任务（直接编辑文件或让 agent 改）

# ④ 实现（新开干净会话）
#    在 Claude Code 输入：/opsx:apply <name>
#    agent 逐项实现并打勾；中断后重开会话再 /opsx:apply 会从首个未勾续做

# ⑤ 校验
#    在 Claude Code 输入：/opsx:verify <name>
#    （不可用则用《提案任务书》该提案的「④ 验收命令 + ⑤ 手工验收清单」手动核验）

# ⑥ 归档（tasks.md 全勾后）
#    在 Claude Code 输入：/opsx:archive <name>
```

## 5. apply / verify / archive 详解

| 命令 | 输入时机 | 做什么 | 你要注意 |
|---|---|---|---|
| `/opsx:apply <name>` | 计划已 Review 完 | agent 读 tasks.md，逐条实现并打勾 | 新开干净会话；中途可打断，重开续做 |
| `/opsx:verify <name>` | apply 后 | 对照 specs/ 场景核验实现是否匹配 | 不通过就回改 proposal/tasks 再 apply |
| `/opsx:archive <name>` | verify 通过、tasks 全勾 | Delta Specs 合入 openspec/specs/，变更移入 changes/archive/ | 归档后该能力即「已交付基线」 |

**关键**：`tasks.md` 是进度真相来源（纯 Markdown 复选框），无隐藏状态。任何时候 `openspec list` 看进行中变更，`openspec show <name>` 看详情。

## 8. 常见问题与排错（Windows 重点）

| 现象 | 原因 | 对策 |
|---|---|---|
| `uv` 命令找不到 | PATH 未刷新 | 重开终端；或把 `%LOCALAPPDATA%\uv` 加入 PATH |
| AgentScope 报 Python 版本低 | 用了系统旧 Python | `uv python install 3.12` 并在 venv 指定；AgentScope 需 >=3.11 |
| SSE 不流式/卡住 | Flask 同步跑异步事件流 | 用 §4.2 的「线程+queue」桥接（技术方案 §7.6），勿直接用 async 路由 |
| 前端跨域报错 | CORS 未开 | backend/app.py 启用 Flask-CORS 允许 5173；或 Vite 代理 /api |
| 模型调用 401 | 密钥错/端点错 | 确认 ModelProvider.base_url 为 OpenAI 兼容；api_key 经 ccswitch 或 DeepSeek；env 覆盖优先 |
| 内置工具误删文件 | 未开 confirm | Permission 默认 confirm（技术方案 §7.7）；生产务必保持 |
| `/opsx:verify` 不存在 | profile 未开 extended | 开 extended；或用手工验收清单等价校验 |
| 中文乱码 | 终端/DB 编码 | SQLite 默认 UTF-8；前端 meta charset=utf-8；文件读写指定 encoding="utf-8" |
