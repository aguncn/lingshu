## 1. 科普：先讲清楚我们在用什么

### 1.1 SDD（Spec-Driven Development，规范驱动开发）
传统流程是「规划→开发→完成」的单向链，一旦进入下一阶段想回头改就很贵。SDD 把开发拆成一系列**可执行动作**：`propose`(提案)→`specs`(规范)→`design`(设计)→`tasks`(任务)→`apply`(实现)→`verify`(校验)→`archive`(归档)。
核心好处：**先对齐「要做什么、做到什么算完」，再写代码**；所有产物是纯 Markdown，你随时可读、可改、可审。

### 1.2 OpenSpec
OpenSpec 是轻量 SDD 框架（MIT，CLI：`openspec`；在 Claude Code 里以 `/opsx:*` 斜杠命令调用）。
每个「变更」落在 `openspec/changes/<name>/`，含四类制品：
- `proposal.md`：为什么做、改了什么（范围）。
- `specs/<capability>/spec.md`：用「可测试需求 + 场景」描述「做到什么算完」。
- `design.md`：关键技术决策（仅复杂变更需要）。
- `tasks.md`：实现清单（复选框），agent 逐项打勾。

闭环：`/opsx:explore`(想清楚) → `/opsx:propose`(出计划) → 你 Review → `/opsx:apply`(逐任务实现) → `/opsx:verify`(对规) → `/opsx:archive`(合入主规格)。

### 1.3 AgentScope 2.06+
阿里达摩院开源的**生产级多智能体框架**。设计哲学：「把 Agent 还原为消息（Msg），框架只提供安全边界、资源隔离、可观测，不让固定编排束缚模型」。
我们用到的核心能力：
- `Agent`：统一智能体类，挂 `Toolkit` 即自动进入 ReAct 推理-行动循环。
- `OpenAIChatModel`：统一模型抽象，**原生支持 OpenAI 兼容端点**——这正是 DeepSeek / ccswitch 的对接方式。
- `Toolkit` + 内置工具（Bash/Read/Write/Edit/Grep/Glob）+ **MCP 客户端**（StdIO / HTTP Streamable / SSE）。
- `reply_stream()`：事件流（文本块、工具调用、需人工确认……），天然适配前端流式渲染与 Human-in-the-Loop。
- `Permission` / `Middleware`：系统级安全边界（白名单、确认、审计），比 prompt 约束可靠。
- `rag`：解析→切块→向量化→检索可插拔，向量库可选 Qdrant / Milvus Lite / MongoDB。

### 1.4 为什么这套技术栈适合「单人 + 能跑起来」
| 选型 | 理由 | 代价/边界 |
|---|---|---|
| uv（Python 包与虚拟环境） | 一条命令建环境、装依赖、锁版本；比 pip+venv 快且可复现 | 需先装 uv（一条 `powershell` 命令） |
| Flask + SQLite | 零运维、单文件库即可跑；Flask 轻、路由直观；SQLite 无需起服务 | 高并发/分布式弱；单人项目完全够用 |
| Vue 3 + Vite + Element Plus | Element Plus 提供企业级表格/抽屉/对话框/菜单，工业风开箱即得，省去自绘组件 | 包体比纯手写大，但开发速度碾压 |
| AgentScope ≥2.06 | 原生 MCP + 流式事件 + 权限边界，正好覆盖「技能/MCP/专家/知识库」装配 | 学习曲线略陡，但本文档已封装好集成层 |
| OpenSpec + Claude Code + ccswitch→DeepSeek | 用国产模型做 AI Coding，规范先行、产物可追溯、可归档 | 需按本文档初始化 OpenSpec |

**一句话**：不引入 Redis / 消息队列 / K8s / 微服务；前后端各一个进程，SQLite 一个文件，AgentScope 单进程推理。能跑、好改、好交付。

## 2. 方法论：OpenSpec 闭环怎么落到本项目

```
需求(PRD) ──▶ /opsx:explore(想清楚范围)
                │
                ▼
          /opsx:propose ──▶ changes/<name>/{proposal.md, specs/, design.md, tasks.md}
                │                ↑ 你在这里 Review、改范围、砍需求
                ▼
          /opsx:apply ──────▶ Claude Code 按 tasks.md 逐条实现并打勾（新开干净会话）
                │
                ▼
          /opsx:verify ─────▶ 对照 specs/ 的需求场景核验实现是否匹配
                │
                ▼
          /opsx:archive ────▶ Delta Specs 合入 openspec/specs/，变更进 archive/
```

**关键纪律（务必遵守）**：
- 每个提案**只做一件事**（一个能力域），范围不超过 PRD 的一个编号组。
- `tasks.md` 每条约 10 条，单条可独立验收（一个接口 / 一张表 / 一个视图）。
- 每完成一个提案就 `apply → verify → archive`，不要攒一堆再归档。
- 新功能**开新会话**做 `/opsx:apply`，避免超长上下文导致 AI 改无关文件。

## 3. 技术选型与合理性（逐条判据）

- **后端 Flask 而非 FastAPI**：本项目以「能跑、好改」为先，Flask 心智负担最低；SSE 用 Flask 生成器+线程桥即可（见 §8.5），无需换框架。若未来要真异步高并发，再切 FastAPI 不迟。
- **SQLite 而非 Postgres**：单人、单机、数据隔离靠「空间→任务」目录即可；SQLite 文件可直接备份、拷贝、演示。多租户在应用层用 `space_id` 隔离，不在数据库层。
- **SQLAlchemy 而非裸 SQL**：模型即文档，迁移可读；本项目实施「轻量迁移器」（见 §6 注），避免 Alembic 复杂度。
- **Vue3+Vite 而非 Vue2/React**：生态新、Element Plus 对 Vue3 最稳；Vite 启动快、HMR 顺手。
- **Element Plus 而非 Naive UI / Ant Design Vue**：企业级组件最全（ElTable/ElDrawer/ElMenu/ElDialog/ElTimeline），最贴合「生产级工业风」；暗色模式内置。
- **AgentScope 而非 LangChain/AutoGen**：原生 MCP + 事件流 + 权限边界，正好映射 PRD 的「技能/MCP/专家/知识库按需装配 + 危险操作二次确认 + 审计」。
- **OpenSpec 而非纯口头需求**：把「做到什么算完」写成 specs，AI 不会跑偏，你验收有依据。

## 4. 总体架构设计

### 4.1 分层架构（文字图）

```
┌──────────────────────────────────────────────────────────────┐
│ 浏览器 (Vue 3 SPA)                                             │
│  左栏：空间/任务/注册中心/自动化/资料库/设置   右栏：会话+细节栏 │
└───────────────┬──────────────────────────┬───────────────────┘
                │  REST (JSON)              │  SSE (流式事件)
                ▼                           ▼
┌──────────────────────────────────────────────────────────────┤
│ Flask API 层 (blueprints)                                      │
│  spaces / tasks / models / prompts / skills / mcp /            │
│  knowledge / experts / automation / scenarios / files /       │
│  chat(SSE) / audit                                            │
├──────────────────────────────────────────────────────────────┤
│ 服务层 (services/)                                            │
│  AgentRuntime │ ModelFactory │ McpClientPool │ KnowledgeService│
│  SkillLoader │ FileStore │ AuditService                     │
├──────────────────────────────────────────────────────────────┤
│ 智能体运行时 (AgentScope ≥2.06)                               │
│  Agent(ReAct) + Toolkit(builtin + MCP工具 + Skill + RAG工具)   │
│  Permission(白名单/confirm) + Middleware(审计/限流)            │
├──────────────────────────────────────────────────────────────┤
│ 持久化 + 文件                                                 │
│  SQLite (SQLAlchemy)  │  本地磁盘 data/spaces/<space>/<task>/  │
└──────────────────────────────────────────────────────────────┘
```

### 4.2 模块职责
- **API 层**：只做参数校验、鉴权（单人项目做轻量）、调用服务层、序列化。**不含业务逻辑**。
- **服务层**：业务逻辑与编排；`AgentRuntime` 是唯一与 AgentScope 对话的地方。
- **AgentRuntime**：根据「任务 + 挂载的能力」构造 `Agent`：选模型→装工具（内置/MCP/技能/RAG）→拼系统提示（场景模板+提示词+约束）→`reply_stream` 桥接到 SSE。
- **ModelFactory**：把 `ModelProvider`(DB) + `ModelConfig`(参数) 转成 AgentScope `OpenAIChatModel`（OpenAI 兼容）。
- **McpClientPool**：按 `MCPConnector` 配置实例化 AgentScope MCP 客户端（StdIO/HTTP），按任务粒度启用，用完 `close()`。
- **KnowledgeService**：文件解析→切块→(可选)向量化→存入 `KnowledgeChunk`；检索返回 top-k 文本块作为 RAG 上下文。
- **FileStore**：文件按「空间→任务」落盘，记录 `FileRecord`。
- **AuditService**：关键动作写 `AuditLog`（谁/做了什么/对象/详情/时间）。

### 4.3 数据流（一次对话）
1. 前端 POST `/api/tasks/<id>/chat` `{message, mountedCaps}`。
2. `chat` 路由取 Task + ModelConfig + 挂载的 Skill/MCP/KB/Expert/Scenario。
3. `AgentRuntime.build()`：ModelFactory→Agent；McpClientPool 注册工具；KnowledgeService 检索注入；拼系统提示。
4. `agent.reply_stream()` 产出事件流 → Flask 生成器转 SSE（`data: {...}\n\n`）→ 前端逐块渲染（打字机/工具调用状态/需确认弹窗）。
5. 消息落 `Message` 表；若产生文件，写 `FileRecord`；动作写 `AuditLog`。

### 4.4 前端布局 ↔ PRD（UI-01~07）
- **左栏全高**：① 新建任务按钮；② 导航（专家·技能·MCP 连接器 / 自动化任务 / 资料库）；③ 任务列表（按空间分组、可搜索）；④ 底部个人信息+设置。
- **右栏**：顶部「常用任务分类 + 提示词模板」；中部「会话（对话 + 文件树/预览）」；底部「可折叠细节栏（模型/技能/资料/MCP/工作空间/权限模板）+ 输入框」。
- **命令面板**：全局 `Ctrl/Cmd+K` 打开（自定义组件）。
- **抽屉**：注册中心（技能/MCP/知识库/专家）、设置中心用 `ElDrawer` 承载。
- **状态/时间线**：`ElTag` 状态徽标；故障/变更记录用 `ElTimeline`。
- **暗色模式**：Element Plus `dark` 主题 + CSS 变量；设置中心切换。

> 全部实体落在 SQLite；用 SQLAlchemy 声明模型。以下为实体 + 关键字段（省略 created_at/updated_at 通用字段）。

### 5.1 实体清单
`Space` `User` `Membership`(空间成员与角色) `Task` `ModelProvider` `ModelConfig` `PromptTemplate` `Skill` `MCPConnector` `KnowledgeBase` `KnowledgeChunk` `Expert` `Automation` `ScenarioTemplate` `Message` `FileRecord` `AuditLog`

### 5.2 关键字段表

| 实体 | 关键字段 | 说明 / 约束 |

| **ModelConfig** | id, task_id(nullable), provider_id, model_name, temperature, max_tokens, timeout, is_default | 每任务/每会话可调参 |
| **PromptTemplate** | id, name, category, domain, content, version, parent_id | 提示词库；version+parent 实现版本化 |
| **Skill** | id, name, description, skill_md, version, enabled | AD-01；skill_md 即 SKILL.md 文本 |
| **MCPConnector** | id, name, transport(`stdio`/`http`), command, args(json), env(json), url, headers(json), trust, enabled | AD-02；env 中密钥脱敏展示 |
| **KnowledgeBase** | id, name, space_id(nullable), embedding_provider, chunk_size, status | AD-03；space_id 为空=全局库 |
| **KnowledgeChunk** | id, kb_id, file_id, content, meta(json), embedding(blob null) | 切块；embedding 可选（默认关键词检索） |
| **Expert** | id, name, description, system_prompt, role, composed_of(json), enabled | AD-04；composed_of 存多专家 id 做协作 |
| **Automation** | id, name, space_id, trigger(`cron`/`once`/`event`), cron_expr, task_template_id, enabled, last_run, next_run | AU-01 |
| **ScenarioTemplate** | id, domain, name, system_prompt, task_template, preset_skills(json), preset_mcp(json), preset_kb, preset_expert | §8 十二域；预设装配 |
| **Message** | id, task_id, role, content, blocks(json), parent_id | 会话历史；blocks 存多模态块 |
| **FileRecord** | id, space_id, task_id, filename, path, mime, size | 文件元数据；实体文件落磁盘 |
| **AuditLog** | id, actor, action, target_type, target_id, detail(json) | 全量操作审计（NF 安全） |

### 5.3 关系要点
- 一个 Space 含多 Task；Task 必属一个 Space（TR-01）。
- Task 1:1 ModelConfig（绑定模型，MD-01）；ModelConfig 引用 ModelProvider。
- Task 多对多挂载 Skill / MCPConnector / KnowledgeBase / Expert（CAP-01~04）→ 用关联表 `task_skill` `task_mcp` `task_kb` `task_expert`（或 JSON 字段，单人项目用关联表更清晰）。
- ScenarioTemplate 与 Task 通过 `scenario_domain` 关联；新建任务选域即套用预设装配。
- FileRecord 与 Space/Task 两级归属，删除任务可级联处理文件（TR-06）。

> **轻量迁移约定**：不用 Alembic。提供 `migrations/` 下编号 `.sql`，启动时由 `migrate.py` 读 `schema_version` 表顺序执行未应用的脚本。每个改动 schema 的提案在 `tasks.md` 里包含「写迁移脚本并执行」一条。

## 7. AgentScope 集成设计（本平台技术底座）

### 7.1 ModelFactory（对接 DeepSeek / ccswitch）
AgentScope `OpenAIChatModel` 原生 OpenAI 兼容。DeepSeek V4 Flash 与 ccswitch 都暴露 OpenAI 兼容端点：

```python
# services/model_factory.py（示意）
from agentscope.model import OpenAIChatModel
import os, json

def build_model(provider: dict, cfg: dict):
    # provider: {type, base_url, api_key_enc}; cfg: {model_name, temperature, max_tokens}
    api_key = decrypt(provider["api_key_enc"])          # 解密，或读环境变量覆盖
    return OpenAIChatModel(
        model=cfg.get("model_name") or provider["default_model"],
        api_key=api_key,
        base_url=provider["base_url"],     # ccswitch 的 OpenAI 兼容 base_url
        # 可选：generation_config={"temperature":..., "max_tokens":...}
    )
```
> 通过 ccswitch 时：`base_url` 填 ccswitch 提供的端点，`api_key` 填 ccswitch key，`model` 填 ccswitch 映射的模型名（如 `deepseek-v4-flash`）。

### 7.2 McpClientPool（CAP-02 / AD-02）
按 `MCPConnector` 配置实例化 AgentScope 客户端：
- `transport=stdio` → `StdIOStatefulClient(name, command, args, env)`，`connect()` 启动本地服务。
- `transport=http` 且 `streamable_http` → `HttpStatefulClient/HttpStatelessClient(name, transport="streamable_http", url)`。
- `transport=http` 且 `sse` → `Http...Client(transport="sse", url)`。
注册到 Toolkit：`await toolkit.register_mcp_client(client)`。用完 `await client.close()`（有状态客户端 LIFO 关闭）。

> P0 只做「连接器管理 + 运行时按任务启用 + 连通性测试」；真实运维 MCP 服务（监控/日志/DB/CMDB）在 P1 接入，协议已就绪。

### 7.3 KnowledgeService（CAP-03 / AD-03）
- 解析：`agentscope.rag.TextParser` 支持 pdf/txt/md/docx。
- 切块：`ApproxTokenChunker(chunk_size, overlap)`。
- 存储：切块写入 `KnowledgeChunk`（SQLite）；**向量化默认关闭**，检索走关键词/BM25（`rank_bm25`）——零外部依赖、可离线跑。
- 可选增强：设 `embedding_provider` 后启用向量检索（`MilvusLiteStore` 或本地 `sentence-transformers` 小模型）。
- 检索：返回 top-k 文本块，拼进系统提示作为 RAG 上下文（满足「必须引用来源」约束）。

### 7.4 SkillLoader（CAP-01 / AD-01）
- `Skill` 表的 `skill_md` 即技能指令文档。运行时：作为系统提示追加段（轻量），或落临时文件经 AgentScope `SkillViewer` 让 Agent 自主阅读执行（P1 增强）。
- v0.3：技能 = 可复用提示词+约束段，挂载即注入；复杂工作流后续用 AgentScope Skill 机制。

### 7.5 Expert（CAP-04 / AD-04）
- 单专家：`system_prompt` 决定人设与流程。
- 多专家协作（P1）：`composed_of` 存专家 id 列表，运行时用 AgentScope `MsgHub`/`Team(Leader-Worker)` 编排（见 §11）。

### 7.6 AgentRuntime + SSE 桥接（§4.3 核心）
Flask 同步框架跑 AgentScope 异步事件流，用「线程+队列」桥接（**关键实现模式**，避免换框架）：

```python
# services/agent_runtime.py（桥接骨架）
import asyncio, queue, threading, json
from flask import Response, stream_with_context
from agentscope.agent import Agent
from agentscope.message import UserMsg

def stream_chat(task, user_msg, caps):
    def gen():
        loop = asyncio.new_event_loop(); asyncio.set_event_loop(loop)
        q: "queue.Queue" = queue.Queue()
        async def run():
            agent = build_agent(task, caps)            # 组装 Model+Toolkit+Prompt
            async for evt in agent.reply_stream(UserMsg("user", user_msg)):
                q.put(evt)
            q.put(None)
        threading.Thread(target=loop.run_until_complete, args=(run(),)).start()
        while True:
            item = q.get()
            if item is None: break
            yield "data: " + json.dumps(serialize(evt=item), ensure_ascii=False) + "\n\n"
    return Response(stream_with_context(gen()), mimetype="text/event-stream")
```
前端用 `fetch` + `ReadableStream` 消费（`EventSource` 不支持自定义头，故不用）。

### 7.7 安全边界（NF）
- `Permission`：内置工具（Bash/Write/Edit）默认 `confirm` 模式（危险操作二次确认）；MCP 最小权限、DB 只读约定写在连接器描述里。
- `Middleware`：自定义审计中间件，每次工具调用/模型调用写 `AuditLog`（谁/动作/对象）。
- 密钥：`ModelProvider.api_key_enc` 用 Fernet 加密；支持环境变量 `LINGSHU_MASTER_KEY` 或 `.env` 覆盖，明文不入库。

## 8. 十二运维场景域如何落地（§8 + §9）

每个域 = 一条 `ScenarioTemplate` 记录：`domain` + `system_prompt`（领域提示词）+ `task_template` + `preset_skills/preset_mcp/preset_kb/preset_expert`（预设装配）。
新建任务时选域，即套用该模板，细节栏仍可逐次覆盖（UI-06）。

| 域 | 系统提示要点 | 预设装配（建议） |
|---|---|---|
| 监控巡检 | 时序+阈值+基线，分级结论+处置建议，抑误报 | 监控 MCP、巡检规范库、报告技能 |
| 日志隐患 | 多行关联，区分噪声/真隐患，给定位线索 | 日志 MCP、日志解析技能 |
| 数据库性能排查 | 基于真实执行计划，给可验证 DDL，禁盲改生产 | DB 只读 MCP、执行计划手册、DBA 专家 |
| 中间件安装配置 | 可执行步骤+回滚，参数带默认值与范围 | Ansible/SSH 技能、官方最佳实践库 |
| 告警 | 降噪/去重/分级/根因关联/抑制 | 告警 MCP、CMDB MCP、告警分级策略库 |
| 故障诊断 | 假设-验证闭环，多维证据，输出影响面+MTTR | 监控+日志+链路 MCP、CMDB、SRE 专家 |
| 变更风险 | 按类型/依赖拓扑评估爆炸半径，列风险+缓解 | CMDB MCP、工单 MCP、变更规范库 |
| 容量预测 | 历史外推，给耗尽时间与扩容建议，标置信区间 | 监控 MCP、时序分析技能、容量模型库 |
| CMDB 数据治理 | 基于事实/拓扑校验，输出可治理工单，不臆造 | CMDB MCP、数据标准库、校验技能 |
| 知识库问答 | 必须引用来源，无法确认显式说明，优先最新版 | 知识库(向量检索)、文档解析技能 |
| 应急预案生成 | 步骤可执行，含回滚+升级，风格一致 | 历史预案库、模板技能、运维负责人专家 |
| 运维脚本编写 | 幂等/参数化/危险操作二次确认/不硬编码密钥 | 代码沙箱、Ansible 技能、内部规范库 |

**统一约束（所有域共用，拼进系统提示）**：禁止臆造数据；危险操作二次确认；回答引用来源；输出结构化（报告/表格/工单）。

## 12. 场景应用小结

灵枢不是「又一个聊天框」，而是把「运维知识（提示词/规范库/SOP）+ 工具（MCP/技能）+ 专家人设」按**场景域**装配成可复用智能体。单人选域建任务→套模板→挂少量能力→对话拿结构化结论（报告/工单/处置建议）。所有产物（规格、提示词、任务、文件）可追溯、可审计、可复用。
